# 微信小程序开发 Skill

面向 Codex 的通用微信小程序开发技能包，帮助你在原生小程序、Taro、uni-app 等项目中实现功能、排查问题，并按平台边界处理登录、授权、支付和发布准备。

## 能做什么

- 新建或修改页面、组件、数据请求与交互状态。
- 定位并修复渲染、生命周期、网络请求、权限和性能问题。
- 实现微信登录、用户授权、敏感能力调用和支付流程的客户端部分。
- 检查适配、加载/空态/失败态、重复点击、会话过期等常见问题。
- 在提交前运行项目现有的 lint、类型检查、测试或构建，并说明未验证的环境依赖。

## 安装

将整个技能目录放到 Codex 的 skills 目录，目录名保持为 `wechat-miniprogram`：

```text
~/.codex/skills/wechat-miniprogram/
├── SKILL.md
└── agents/
    └── openai.yaml
```

例如：

```bash
git clone https://github.com/wq678/wechat-miniprogram-skill.git \
  ~/.codex/skills/wechat-miniprogram
```

安装后新开一个 Codex 对话；如界面提供技能列表，也可以在其中确认“微信小程序开发”已出现。

> Windows 通常可将 `~/.codex` 理解为用户目录下的 `.codex` 文件夹。若你的 Codex 使用了自定义 skills 目录，请放入该目录。

## 调用方式

可直接描述任务，Codex 会在小程序开发任务中自动选择本技能；也可以显式调用：

```text
$wechat-miniprogram 为现有小程序新增商品收藏功能，复用项目现有请求层，并补齐加载、失败和空态。
```

更多示例：

```text
$wechat-miniprogram 排查登录态过期后接口不断重试的问题，保持当前项目架构不变。

$wechat-miniprogram 为原生微信小程序新增地址选择页，处理授权被拒绝、手动前往设置和返回后的刷新。

$wechat-miniprogram 检查支付下单流程：金额、订单状态和支付签名必须由服务端确认。
```

## 使用建议

提供以下信息可以让实现更准确：

- 项目路径或相关页面/组件。
- 技术栈：原生小程序、Taro、uni-app 或其他框架。
- 目标功能、交互稿或接口约定。
- 最低基础库版本、云开发/后端环境，以及是否可使用真机和微信开发者工具。
- 已有的报错、复现步骤或截图。

技能会先识别项目结构与既有约定，再在对应代码中进行修改，避免把不同框架的 API 混用。

## 登录、授权与支付边界

本技能将下列数据视为服务端责任，**不会**建议写入小程序源码或客户端配置：

- AppSecret、商户密钥、云管理员凭据、私钥和长期 Token。
- `session_key`、支付签名、服务端访问令牌。
- 价格、库存、订单最终状态和角色权限等可信业务判断。

推荐的登录流程是：客户端调用 `wx.login()` 获取一次性 `code`，经 HTTPS 发给业务后端；后端完成与微信的交换和校验后，再返回应用自身的短期会话信息。支付完成后，应由服务端查询或接收已验证的支付结果，不能只依据客户端回调判定订单成功。

## 验收范围

技能会尽量覆盖与改动相关的：

- 加载、空数据、网络错误、超时、权限拒绝和会话失效。
- 窄屏/宽屏、安全区、返回导航和重复操作。
- 现有 lint、类型检查、测试和构建。

需要开发者账号、真实后端、支付资质、云资源、真机权限或最终发布审核的部分，会明确标注为需要你手动验证的项目。
